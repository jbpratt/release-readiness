# AGENTS.md

Guidance for agents (Claude Code, Codex, etc.) working in this repository.

## Project

Release readiness dashboard for the Quay container registry: a Go backend plus
an embedded React/PatternFly SPA, backed by SQLite. Background sync loops read
Konflux Snapshots and Releases through the Kubernetes API, ART build history,
FBC images, the Red Hat container catalog, Prow periodics, CVE scans from
Tekton Results, and JIRA issues per release; one binary serves the REST API
(`/api/v1/`) and the SPA. `README.md` is the reference for what each source
ingests and what the API fields mean.

## Build, test, lint

Build the web bundle first: `web/embed.go` embeds `web/dist/`, which is
gitignored, so the Go build fails on a fresh clone without it. CI's Go job
uses an empty `web/dist/index.html` stub instead.

```bash
cd web && npm ci && npm run build && npm run lint && npm test && cd ..
go build -o release-readiness ./cmd/release-readiness/
go test ./...
golangci-lint run
```

- Single package: `go test ./internal/jira/`.
- `npm run build` is `tsc -b && vite build`; `npm test` runs the `node --test`
  util tests listed in `web/package.json`.
- Go lint config: `.golangci.yml`. Web lint/format: Biome, `web/biome.json`
  (CI runs `npx biome ci src/`).
- CI (`.github/workflows/ci.yaml`) runs on Node 24 and also builds the image.
- Container: `podman build -f deploy/Containerfile -t release-readiness .`

## Run locally

```bash
# The kubeconfig needs list on Snapshots and Releases in -namespace; the CVE
# scan sync also needs a bearer token in it.
KUBECONFIG=<path> go run ./cmd/release-readiness -addr :8088 -db /tmp/rr.db

# Separate terminal: Vite dev server on 5173, proxies /api to localhost:8088
cd web && npm run dev
```

Flags (env fallback in parentheses; defaults point at production services):

- `-addr` (default `:8080`), `-db` (default `dashboard.db`).
- Konflux: `-kubeconfig` (`KUBECONFIG`; empty uses the in-cluster service
  account), `-namespace` (`KONFLUX_NAMESPACE`, default `art-quay-tenant`),
  `-konflux-poll-interval`, `-konflux-ui-url` (`KONFLUX_UI_URL`).
- JIRA: `-jira-url` (`JIRA_URL`), `-jira-api-url` (`JIRA_API_URL`),
  `-jira-email` (`JIRA_EMAIL`), `-jira-token` (`JIRA_TOKEN`), `-jira-project`
  (`JIRA_PROJECT`, default `PROJQUAY`), `-jira-poll-interval`.
- `-github-token` (`GITHUB_TOKEN`): read-only token for the FBC reconciler's
  GitHub commit lookups; empty reads GitHub unauthenticated.
- FBC JIRA writer, off until `-jira-write` (`JIRA_WRITE`) is true and
  `-jira-write-email` (`JIRA_WRITE_EMAIL`) and `-jira-write-token`
  (`JIRA_WRITE_TOKEN`), a credential separate from the read one, are set.
- `-art-build-history-url`, `-tekton-results-url`, `-catalog-url`,
  `-art-fbc-quay-url`: empty disables that source.
- Prow: `-prow-jobs` (`PROW_JOBS`, `job_name=konflux_application[,...]`),
  `-prow-job-pattern` (`PROW_JOB_PATTERN`, a `^`-anchored job name regexp
  whose `major` and `minor` groups give the application
  `quay-<major>-<minor>`; a `-prow-jobs` entry for the same job wins),
  `-prow-interval`.
- Shipment MRs: `-gitlab-url` (empty disables), `-gitlab-token`
  (`GITLAB_TOKEN`; empty reads anonymously), `-shipment-project`,
  `-ocp-build-data-url`, `-gitlab-poll-interval`.
- `-stage-release-plan-pattern` (`STAGE_RELEASE_PLAN_PATTERN`): ReleasePlan
  names whose Releases are image STAGE.
- `-retention` (default `720h`, 0 disables): daily prune of data no release
  needs, and the age past which Konflux and Prow skip it on ingest.

`cmd/release-readiness/main.go` is the source of truth for the flag set.
`dev/shots.py` takes full-page screenshots of a running instance (see
`dev/README.md`).

## Data sources and freshness

Each loop is started in `main.go` only when its inputs are set:

| Source (`sync_status` name) | Starts when |
|---|---|
| Konflux Snapshots/Releases (`konflux`) | a kube client can be built; otherwise `konflux` is reported failing |
| JIRA (`jira`) | `-jira-token` is set |
| ART build resolve and history, FBC render, FBC JIRA reconciler (`art-builds`, `art-history`, `fbc-render`, `reconcile`) | `-art-build-history-url` is set |
| Catalog (`catalog`) | `-catalog-url` is set |
| Prow (`prow`) | `-prow-jobs` names a job or `-prow-job-pattern` is set |
| GitLab shipment MRs (`shipment-mrs`) | `-gitlab-url` is set |
| Retention prune (`retention`) | `-retention` is above 0 |
| Image scans (`image-scans`) | `-tekton-results-url` is set, the kube client exists, ART is enabled, and the credential has a bearer token |

Each pass reports to `internal/syncstatus/`. A success is written to the
`sync_status` table and seeds the source's last success on restart.
`GET /api/v1/sync-status` returns `sources` (each source's `last_success`) and
`problems`: a source whose last pass failed, or with no success in
max(3 x interval, 10 minutes), counted from process start when the stored
success is older.

## Schema and sqlc

After a schema or `internal/db/queries/*.sql` change, run `sqlc generate`
(config `sqlc.yaml`) with sqlc v1.30.0, the version in the generated headers
and in `.github/workflows/sqlc.yaml`, and commit `internal/db/sqlc/` in the
same change.

`db.Open` applies the `migrations` list in `internal/db/db.go` in order, each
in its own transaction, and records the count in `PRAGMA user_version`; a DB
newer than the binary fails to open. Migration 1 is the baseline:
`schema.sql` plus the `jira_issues.status` column. `schema.sql` is never
edited, since only migration 1 runs it: every schema change, new tables
included, is a new migration appended to the list. Put its SQL in a new `.sql`
file under `internal/db/` that the migration embeds, and add that file to the
`schema:` inputs in `sqlc.yaml` so generated code matches. Existing DB files
upgrade in place.

## Gotchas

- Without JIRA nothing creates `release_versions` rows, so the overview is
  empty. JIRA also maps each fixVersion to its Konflux application
  (`quay-v3.18.1` -> `quay-3-18`).
- The image scan sync reuses the Konflux credential against the Tekton Results
  route; a kubeconfig without a bearer token (e.g. client certificates)
  disables it with a warning in the log.
- `deploy/rbac.yaml`'s Role and RoleBinding must live in the Konflux namespace
  the app reads; they grant list on Snapshots and Releases and get/list on
  Tekton Results `results` and `records`.
- The SQLite DB is persisted on the PVC. Delete the old DB file when upgrading
  across the move to the Kubernetes source.
